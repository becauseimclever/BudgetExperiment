### Design Rationale

The implementation maintains backend-agnostic separation while providing sensible defaults:
- **No hardcoded backend text** — labels adapt or remain generic
- **Smart endpoint swapping** — only auto-swaps if default, preserves custom endpoints
- **Minimal state** — endpoint and backend are the only user-configurable values
- **Zero breaking changes** — existing Ollama deployments work unchanged
- **Extensible** — adding a new backend only requires enum, service class, and DI line; no UI changes
