# Orchestration Log: Lucius Captive Dependency Fix

**Timestamp:** 2026-04-09T21:46:32Z

## Work Summary

Fixed captive dependency bug in Blazor WASM client.

**Problem:**
- `IFeatureFlagClientService` registered as `AddSingleton`
- Service injects `HttpClient` (Scoped lifetime)
- Singleton service consuming Scoped dependency throws `InvalidOperationException` at WASM boot

**Solution:**
- Changed registration from `AddSingleton` to `AddScoped` in `src/BudgetExperiment.Client/Program.cs`
- Semantically identical in Blazor WASM (one scope per page lifecycle)
- Eliminates captive dependency violation

## Results

- **Test Status:** 2,824 tests pass

- **Deployment Ready:** Yes

## Changes

**File:** `src/BudgetExperiment.Client/Program.cs`
- Line: Service registration block
- Change: `services.AddSingleton<IFeatureFlagClientService, FeatureFlagClientService>()` → `services.AddScoped<IFeatureFlagClientService, FeatureFlagClientService>()`

## Technical Notes

Captive dependency is a DI anti-pattern where a singleton captures a scoped or transient dependency. The WASM container enforces scoping stricter than server scenarios, making this violation surface immediately at bootstrap rather than at runtime.
